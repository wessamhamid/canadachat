# Security policy

canadachat handles visitors' own AI API keys in transit and fetches pages from government websites, so
security reports are taken seriously.

## Reporting

Please **do not** open a public issue for a security problem. Use GitHub's private vulnerability reporting
on this repository (Security tab, "Report a vulnerability"). You'll get an acknowledgement within 7 days and
a fix or a plan within 30 days for confirmed issues.

Please include what you found, how to reproduce it, and what you think the impact is. Reports about the
live site are welcome too; please test gently (no load tests, no scraping of the index).

## In scope

* Anything that could expose or store a visitor's API key (it must exist only in the visitor's browser and
  in memory for the duration of one request).
* Answers linking to non-official pages, or content from crawled pages steering the model (prompt injection).
* Server-side request forgery through crawl sources, sitemaps or live page fetches.
* Failures of the redaction of identifiers (SIN, health card, card and phone numbers, email addresses,
  postal codes) before text reaches a model.
* Bypasses of rate limits, or ways to make the server test API keys in bulk.

## Out of scope

* Vulnerabilities in the government websites the index links to. Report those to the site owner.
* Reports generated by automated scanners without a demonstrated impact.

## Supported versions

Only the `main` branch is supported; there are no long-lived release branches.
